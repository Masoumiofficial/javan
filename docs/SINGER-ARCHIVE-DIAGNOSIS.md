# بررسی: چرا صفحهٔ `singer` (آرشیو خواننده) نمایش داده نمی‌شود؟

**تاریخ:** ۲۰۲۶-۱۰-۱۵ · **فایل‌های مرتبط:** `taxonomy-singer.php`، `single.php`، `myfunctions.php`، `functions.php` (رمزگذاری‌شده) · **وضعیت:** علت‌های ممکن شناسایی، موارد قابل‌اثبات در کد رفع شد، تست نهایی روی سایت شما لازم است.


---

> ### ⚠️ اصلاح مهم — «شبکهٔ ایمنی» نسخهٔ اول پس گرفته شد (پیش‌فرض: خاموش)
>
> ۱. **مقصر اصلی رگرسیون:** نسخهٔ اولی که در `myfunctions.php` گذاشتیم **پیش‌فرض روشن** بود و با فیلتر `register_taxonomy_args` روی تنظیمات تاکسونومیِ ثبت‌شدهٔ خودِ سایت دست می‌گذاشت. اگر `/singer/…` **قبلاً کار می‌کرد** و بعد از این تغییرات بالا نیامد، همین بلوک مشکوک شمارهٔ یک است: بازنویسی `public/publicly_queryable/rewrite` می‌تواند اسلاگ و ترتیب قوانین را عوض کند و آرشیو را ۴۰۴ کند.
>    اکنون: پیش‌فرض `false`، فیلتر `register_taxonomy_args` **کامل حذف شد**، و هیچ تاکسونومیِ موجودی دست‌کاری یا دوباره ثبت نمی‌شود.
> ۲. **ایراد اثبات‌شدهٔ دوم:** بلوک ما با الگوی `?> … <?php` به انتهای `myfunctions.php` چسبانده شده بود. هر فاصله/خطی که بعد از `?>` بیاید در **هر درخواست چاپ می‌شود** (خروجی ناخواسته، خرابی هدر/ریدایرکت/کش). همهٔ این اتصال‌ها حذف شد و فایل داخل یک ناحیهٔ `<?php` می‌ماند.
> ۳. **بازگشت به عقب (کوچک‌ترین قدم):** فایل `myfunctions.php` قبلی را برگردانید، یا فقط بلوک انتهای فایل را پاک کنید. توجه: خودِ `taxonomy-singer.php` یک «قالب نمایش» است و **به‌تنهایی نمی‌تواند ۴۰۴ بسازد**؛ فقط ظاهر/محتوای آرشیو را عوض می‌کند.
> ۴. برای فعال‌کردن دوبارهٔ شبکهٔ ایمنی (فقط اگر گزارش تشخیصی بگوید تاکسونومی `singer` **ثبت نشده** است): `define( 'JAVANSEDA_SINGER_FIX', true );` در `wp-config.php`.
## ۱) خلاصهٔ تشخیص در یک نگاه

| # | علت محتمل | نشانه | آیا در کد رفع شد؟ |
|---|---|---|---|
| ۱ | تاکسونومی `singer` ثبت نشده یا غیرعمومی ثبت شده → آدرس `/singer/…` خطای ۴۰۴ می‌دهد | لینک خواننده → «۴۰۴ / محتوایی پیدا نشد» | ✅ ولی **پیش‌فرض خاموش** — ثبت جایگزین فقط با `JAVANSEDA_SINGER_FIX = true` و آن هم وقتی هیچ تاکسونومی/پست‌تایپی با نام `singer` وجود ندارد (بخش ۳) |
| ۲ | قوانین پیوند یکتا (rewrite) کهنه‌اند و آرشیو تاکسونومی ۴۰۴ می‌شود | تاکسونومی هست ولی آدرس کار نمی‌کند | ✅ ولی **پیش‌فرض خاموش** — بازسازی یک‌بارهٔ نرم، فقط در همان حالت فعال‌شده (بخش ۳) |
| ۳ | مقدار فیلد `musics_type` با `mp3|mp4|album` یکی نیست (برچسب، حروف بزرگ، «آهنگ»، کلید متفاوت) → هر سه بخش قالب خالی می‌شد | صفحه بالا می‌آید ولی هیچ آهنگی ندارد؛ فقط هدر خواننده | ✅ بله — بازنویسی `taxonomy-singer.php` (بخش ۲) |
| ۴ | سایت آرتیست‌ها را با «برچسب» می‌سازد نه ترم `singer` | ترم `singer` خالی است ولی `/tag/...` کار می‌کند | ✅ تشخیص خودکار در گزارش (بخش ۴) |
| ۵ | آرشیو سالم است ولی خوانندهٔ موردنظر هیچ نوشته‌ای وصل‌شده ندارد | متن «آهنگی ثبت نشده» | ✅ پیام روشن و راهنما اضافه شد |

> نکتهٔ مهم: تاکسونومی `singer` **در هیچ فایل خوانای قالب ثبت نشده است** (بررسی شد: در `myfunctions.php`، `functions.php`ِ خوانا، و همهٔ قالب‌ها هیچ `register_taxonomy` وجود ندارد). پس ثبت آن داخل `functions.php` رمزگذاری‌شده است یا وجود ندارد. این مهم‌ترین سرنخ است: اگر آن فایل به هر دلیلی (نسخهٔ PHP، شرایط میزبان، فایل ناقص) ثبت را انجام ندهد، آرشیو خواننده ایستا ۴۰۴ می‌شود.

## ۲) چه چیزی در `taxonomy-singer.php` خراب بود (و رفع شد)

نسخهٔ قبلی این سه کوئری را می‌زد:

```php
$query  = new WP_Query( array( ..., 'meta_query' => array( array( 'key' => 'musics_type', 'value' => 'mp3',   'compare' => '=' ) ) ) );
$query1 = new WP_Query( array( ..., 'meta_query' => array( array( 'key' => 'musics_type', 'value' => 'mp4',   'compare' => '=' ) ) ) );
$query2 = new WP_Query( array( ..., 'meta_query' => array( array( 'key' => 'musics_type', 'value' => 'album', 'compare' => '=' ) ) ) );
```

سه ایراد جدی:

1. **هر سه با تطبیق دقیق (`compare = '='`) کار می‌کنند.** اگر در نوشته‌ها مقدار `musics_type` دقیقاً `mp3` / `mp4` / `album` نباشد — مثلاً برچسب فارسی، حرف بزرگ، `mp3 128`، یا کلید متفاوت — **هر سه بخش خالی می‌شوند** و صفحه فقط هدر خواننده را نشان می‌دهد. کاربر این حالت را «صفحه نمایش داده نمی‌شود» می‌بیند. این محتمل‌ترین علت ظاهری است.
2. **صفحه هیچ حالت خالی (empty state) ندارد.** اگر چیزی نبود، کاربر پیام نمی‌بیند؛ فقط کادر سفید.
3. **سه کوئری و `posts_per_page => -1` در هر سه، در سه نقطهٔ دیگر تکرار شده بود** (در کل ۶ کوئری در یک صفحه) — کندی و بار اضافی.

**نسخهٔ جدید (فایل چهارم بستهٔ جایگزینی):**

- **یک کوئری** به‌جای شش کوئری؛ نتایج در PHP دسته‌بندی می‌شوند (سریع‌تر و سبک‌تر).
- مقدار `musics_type` **نرمال‌سازی** می‌شود (`strtolower` + `trim`) و یک **نگاشت مترادف** دارد: `mp3/audio/آهنگ/song` → صوتی، `mp4/video/موزیک ویدیو/کلیپ` → تصویری، `album/آلبوم` → آلبوم. قابل تغییر با فیلتر `javanseda_artist_type_map`.
- **هیچ نوشته‌ای پنهان نمی‌ماند:** هر مقدار ناشناخته در بخش «سایر موارد» نمایش داده می‌شود (و نام مقدارها در سورس کامنت می‌شود تا سریع پیدا شود).
- **حالت خالی انسانی:** «آهنگی برای این خواننده ثبت نشده است» + راهنمای اینکه فیلد خواننده را در نوشته‌ها وصل کنند + لینک بازگشت.
- **محافظ ترم:** اگر `get_queried_object()` یک ترم نباشد → پیام «صفحهٔ این خواننده در دسترس نیست» با راهنمای بازسازی پیوندهای یکتا، به‌جای صفحه یا خطای خالی.
- **همهٔ کلاس‌های CSS قبلی حفظ شده‌اند** (`artist_box_tarlanweb`، `artist_resume_box`، `song_boxs`، `songs_title_box` و…) پس ظاهر قالب تغییر نمی‌کند. پشتیبانی صفحه‌خوان هم اضافه شد (`esc_html`/`esc_url`).

## ۳) «شبکهٔ ایمنی» در `myfunctions.php` — پیش‌فرض خاموش

```php
if ( ! defined( 'JAVANSEDA_SINGER_FIX' ) ) {
	define( 'JAVANSEDA_SINGER_FIX', false );   // پیش‌فرض: خاموش، هیچ رفتاری را تغییر نمی‌دهد
}

if ( JAVANSEDA_SINGER_FIX ) {
	/* ثبت جایگزین — فقط اگر تاکسونومی و پست‌تایپ هم‌نام *وجود نداشته باشند* */
	add_action( 'init', function () {
		if ( taxonomy_exists( 'singer' ) ) { return; }   // ثبت‌شده است؛ دست نزن
		if ( post_type_exists( 'singer' ) ) { return; }  // پست‌تایپ هم‌نام هست؛ ثبت تاکسونومی + rewrite = ۴۰۴
		register_taxonomy( 'singer', array( 'post' ), array(
			'public' => true, 'publicly_queryable' => true, 'show_in_rest' => true,
			'rewrite' => array( 'slug' => 'singer', 'with_front' => false ),
		) );
	}, 99 );   // اولویت ۹۹ = بعد از قالب و افزونه‌ها

	/* بازسازی یک‌بارهٔ نرم قوانین پیوند یکتا (بدون دست‌زدن به .htaccess) */
	add_action( 'admin_init', function () {
		if ( ! taxonomy_exists( 'singer' ) ) { return; }
		if ( get_option( 'javanseda_singer_rewrite_version' ) === '2.0.0' ) { return; }
		flush_rewrite_rules( false );
		update_option( 'javanseda_singer_rewrite_version', '2.0.0' );
	} );
}
```

- **هیچ فیلتر `register_taxonomy_args` وجود ندارد.** تاکسونومیِ ثبت‌شدهٔ خودِ سایت هرگز بازنویسی، دوباره‌ثبت یا جابه‌جا نمی‌شود. (این همان چیزی بود که در نسخهٔ اول باعث رگرسیون شد و حذف شد.)
- در حالت پیش‌فرض، این بلوک **صفر کار** انجام می‌دهد: نه `register_taxonomy`، نه rewrite، نه هوک روی درخواست.
- بازسازی rewrite فقط **یک بار** و فقط در همان حالت فعال اجرا می‌شود (با گزینهٔ نسخه‌دار `javanseda_singer_rewrite_version = 2.0.0`).
- گزارش تشخیصی (بند ۴) **همیشه** فعال است — خواندنی، فقط برای مدیر — و مستقل از وضعیت `JAVANSEDA_SINGER_FIX`.

## ۴) چگونه روی سایت خودتان قطعی تشخیص بدهیم

با حساب **مدیر** وارد شوید و این آدرس‌ها را باز کنید (فقط برای مدیر کار می‌کند و خروجی متن ساده است):

| آدرس | چه چیزی می‌گوید |
|---|---|
| `https://ahangban.ir/?ab_singer_diag=1` | آیا تاکسونومی `singer` هست؟ `public`/`publicly_queryable`/`rewrite` چه وضعی دارند؟ چند ترم دارد؟ لینک ترم‌ها سالم است؟ ساختار پیوند یکتا چیست؟ |
| `https://ahangban.ir/?ab_singer_diag=1&ab_singer_term=mohsen-yeganeh` | ترم «محسن یگانه» هست یا نه؟ `term_link` سالم است؟ چند نوشته به آن وصل است؟ و **پرتکرارترین مقدارهای `musics_type`** در آن نوشته‌ها چیست؟ |

خواندن نتیجه:

- اگر `taxonomy_exists(singer): NO` → علت اصلی همین است؛ کد بخش ۳ آن را خودکار حل می‌کند (اگر حل نشد، یعنی فایل رمزگذاری‌شدهٔ `functions.php` اصلاً اجرا نمی‌شود و باید کل آن فایل بررسی شود).
- اگر `public: NO` یا `publicly_queryable: NO` → فیلتر بخش ۳ آن را روشن می‌کند.
- اگر ترم هست ولی `count: 0` → نوشته‌ها به خواننده وصل نشده‌اند (فیلد `singer`/خواننده در نوشته‌ها تنظیم شود).
- اگر ترم نیست ولی «برچسبی با همین نام وجود دارد» چاپ شد → سایت شما آرتیست را با **برچسب** نگه می‌دارد؛ در آن حالت گزینهٔ «مطالب بیشتر خواننده بر اساس برچسب» قالب را روشن کنید یا ترم‌های `singer` را بسازید.
- اگر پرتکرارترین `musics_type` مثلاً `آهنگ` یا `MP3` بود → نسخهٔ قدیم آرشیو آن را نمی‌دید، ولی فایل جدید همه را نشان می‌دهد.

**راه‌حل دستی (۳۰ ثانیه‌ای) برای علت ۲:** پیشخوان ← تنظیمات ← پیوندهای یکتا ← بدون تغییر «ذخیرهٔ تغییرات» را بزنید؛ این کار قوانین را بازسازی می‌کند.

## ۵) نکته‌های باقی‌مانده (خارج از دست من)

1. **`functions.php` رمزگذاری‌شده است.** اگر ثبت تاکسونومی داخل آن خراب/غیرفعال باشد، پایدارترین راه، گرفتن نسخهٔ سالم از فروشنده است؛ کد جدید ما فقط «شبکهٔ ایمنی» است.
2. **`posts_per_page => -1`** در فایل جدید هم پیش‌فرض است تا هیچ آهنگی پنهان نشود. برای سایت‌های پربازدید توصیه می‌کنم سقف بگذارید:
   ```php
   add_filter( 'javanseda_artist_posts_limit', function () { return 120; } );
   ```
   (در این حالت تعداد آیتم‌های هر بخش در هدر همان بخش نمایش داده می‌شود؛ اگر خواستید صفحه‌بندی اضافه کنم، بگویید.)
3. **`taxonomy-singer.php` در حالت شب/روشن** از همان پالت سازمانی استفاده می‌کند (هیچ رنگ اختصاصی در این فایل نیست)، پس با ریدیزاین هم‌خوان است.

## ۶) فایل‌هایی که برای این رفع باید جایگزین شوند

| فایل | چرا |
|---|---|
| `taxonomy-singer.php` | بازنویسی آرشیو خواننده (بخش ۲) — **فایل چهارم بستهٔ جایگزینی** |
| `myfunctions.php` | شبکهٔ ایمنی ثبت تاکسونومی + بازسازی rewrite + گزارش تشخیصی (بخش ۳ و ۴) |
| `single.php` / `style.css` | از مراحل قبلی؛ اگر قبلاً جایگزین کرده‌اید نیازی به تکرار نیست |

پس از جایگزینی: یک‌بار پیشخوان را باز کنید (تا بازسازی rewrite انجام شود)، سپس صفحهٔ یک خواننده را تست کنید.
